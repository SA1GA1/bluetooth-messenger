# ТЗ: OffGrid Messenger

> Актуальный контракт MVP (2026-10-16). При расхождении с исходным ТЗ ниже действует этот раздел.
>
> Android 12+ (API 31). Работа без интернета и Google Play services. BLE advertising/scanning + GATT для обнаружения и коротких пакетов, системный Wi-Fi Direct для вложений. Nearby Connections исключён. Камера CameraX + встроенный ZXing.
>
> PIN из 6 цифр обязателен. Холодный запуск и явное закрытие требуют PIN; после сворачивания — включённая биометрия, после первого отказа/ошибки/отмены — PIN. Сворачивание блокирует сразу. Таймаут 1/3/5/15 минут (по умолчанию 5) действует при бездействии в открытом приложении. При блокировке/фоне обмен останавливается, БД закрывается, рабочие секреты освобождаются. Забытый PIN: только подтверждённый локальный сброс.
>
> Одного сканирования QR достаточно: второй пользователь подтверждает запрос, оба сверяют код знакомства и независимо вводят имена. QR содержит UUID и публичные ключи, без имени. Доверие устанавливается только после взаимного подтверждения.
>
> Только локальное удаление; «удалить у всех»/Recall исключено. Очередь и Ack устойчивы к перезапуску; Ack после сохранения; повтор пакета не создаёт дубликат. Очистка истории отменяет её очередь и удаляет вложения.
>
> Группой управляет создатель. Участник может выйти. Изменение состава меняет GroupKey; состав и сообщения подписаны. Каждый отправитель доставляет собственные сообщения каждому адресату напрямую. Mesh и передача управления отсутствуют.
>
> Идентичность: полный UUID, отдельные неэкспортируемые P-256 signing/agreement keys в Keystore. StrongBox → TEE, без скрытого software fallback. ECDH + HKDF-SHA256 + AES-256-GCM + ECDSA-SHA256. Секрет SQLCipher случайный, защищён Keystore. Бэкапы/перенос приватных данных отключены.
>
> Лимиты: текст 16 КиБ UTF-8, публичный текст 2 КиБ, фото 10 МиБ, файл 50 МиБ, группа до 8 человек включая создателя. Публичный режим без E2E и подписей, сообщения живут 24 часа, максимум 20 устройств. Точные метры не показываются. Тёмная тема фиксированная.
>
> Вне MVP: фоновая доставка, mesh, ratchet, rotating ID, докачка, голосовые сообщения, светлая тема и остальной roadmap. Радиосвязь требует приёмки на двух физических устройствах, группы — на трёх. Сейчас доступен один телефон; автоматические проверки не заменяют аппаратную приёмку.

## 1. Общее описание

**OffGrid** — peer-to-peer мессенджер, работающий полностью без интернета. Связь между устройствами осуществляется через Bluetooth Low Energy (discovery + короткие команды) и Wi-Fi Direct (передача данных и файлов). Все личные сообщения шифруются end-to-end. Приложение не использует серверную инфраструктуру.

**Целевая аудитория:** пользователи в условиях отсутствия связи (метро, самолёты, походы, фестивали, конференции, зоны катастроф).

## 2. Функциональные требования (MVP)

### 2.1. Первый запуск и аутентификация

**Генерация ключей:**
- При первом запуске генерируется пара ключей ECIES P-256 в Android Keystore (StrongBox/TEE, non-exportable).
- `user_id` генерируется автоматически (UUID, сокращённый до 8 символов). **Пользователю не отображается.** Используется только внутри приложения и в BLE-маяках.
- Предложение установить PIN-код (6 цифр) или включить биометрию (отпечаток/лицо) через BiometricPrompt.

**Повторный вход:**
- Экран блокировки: PIN или биометрия.
- **Таймаут авто-выхода:** если приложение N минут в фоне или без действий в foreground — экран блокировки. Настраивается: 1 / 3 / 5 / 15 минут (по умолчанию 5).

---

### 2.2. Главный экран (Чаты)

**Bottom Navigation:** Чаты | Рядом | Настройки

**Список чатов:**
- Аватар (круг, инициалы + цвет), онлайн-индикатор (зелёная точка, если устройство в радиусе BLE).
- Имя контакта (пользователь вводил сам при добавлении).
- Последнее сообщение (обрезка до 2 строк).
- Время последнего сообщения.
- Бейдж непрочитанных.
- Иконка замка — E2E активен.

**Pull-to-refresh:** ручное обновление статуса онлайн.

**FAB (+):** Bottom Sheet:
- Показать мой QR.
- Сканировать QR.
- Найти рядом.
- Создать группу.

---

### 2.3. Добавление контакта через QR

**Экран «Мой QR»:**
- QR-код содержит только **публичный ключ** + `user_id` (внутренний).
- **Нет** `display_name`. Никаких имён в QR.
- Кнопка переключения: «Показать QR» / «Сканировать QR».

**Экран сканирования:**
- CameraX + ML Kit Barcode Scanning.
- При успешном сканировании:
  - Валидация публичного ключа.
  - Открывается диалог: «Введите имя контакта» (пустое поле, обязательно для заполнения).
  - Сохранение: `name` (ручной ввод), `user_id`, `public_key`.
  - Возврат на главный экран.
  - Системное сообщение в чате: «Ключи обменяны. E2E шифрование активно.»

---

### 2.4. Поиск рядом

**Постоянное сканирование:**
- BLE Scan работает постоянно, пока пользователь на экране «Рядом» или пока приложение в foreground.
- Advertising (маяк) работает всегда, пока приложение активно (foreground).

**Режим «Контакты» (по умолчанию):**
- Показывает только тех, с кем уже был обмен ключами.
- Список: аватар, имя (ручной ввод), онлайн-индикатор.

**Режим «Все в радиусе» (Broadcast):**
- Переключатель в шапке.
- Показывает ВСЕ устройства с включённым приложением.
- **Анонимность:** отображается «Аноним (5 м)». Никаких имён, никаких ID.
- Только plain-text. Нет E2E, нет подписи.
- Сообщения эфемерные: хранятся 24 часа, потом удаляются.
- **Ограничение:** отображается максимум 20 последних анонимных устройств.
- Возможность ответить в тот же broadcast (тоже анонимно).

**Отправка сообщения контакту из «Рядом»:**
- Тап по контакту → переход в 1-to-1 чат.
- Если контакт вне зоны — сообщение в статусе «⏳ Ожидание».

---

### 2.5. Личный чат (1-to-1, E2E)

**Шапка:**
- Имя контакта (которое ввёл пользователь при добавлении).
- Подпись: «В сети» или «Вне зоны · Ожидание».
- Иконка (i) → детали:
  - Отпечаток ключа (для сверки голосом).
  - QR контакта (только для проверки, не для обмена).
  - Удалить чат.
  - **Очистить историю** — удаляет все сообщения в чате (только локально, у собеседника остаются).

**Зона сообщений:**
- Пузыри: входящие (слева, светлые) / исходящие (справа, тёмные).
- Галочки статуса:
  - ⏳ Ожидание (в очереди, получатель не в радиусе).
  - ✓ Отправлено (ушло в эфир).
  - ✓✓ Доставлено (получен Ack).
  - 👁 Прочитано (опционально, можно отключить в настройках).
  - ❌ Ошибка.

**Ввод:**
- Текстовое поле.
- Кнопка скрепки: вложения (фото, файл, геолокация).
- Кнопка отправки.

**Долгий тап на сообщение:**
- Копировать текст.
- Удалить у себя.
- Удалить у всех (Recall) — **только если сообщение ещё не доставлено** (статус ⏳ или ✓). Если ✓✓ — recall невозможен.
- Информация о сообщении (время, статус, размер).

---

### 2.6. Групповой чат

**Создание:**
- Из FAB «Создать группу».
- Выбор участников из списка 1-to-1 контактов (только те, с кем есть E2E).
- Название группы (обязательно, вводит создатель) + аватар (инициалы или выбранный цвет).

**Механика ключей:**
- При создании генерируется GroupKey (AES-256).
- GroupKey рассылается каждому участнику через его 1-to-1 E2E канал.
- Все сообщения в группе шифруются GroupKey.

**Offline-участники (Store-and-Forward):**
- Если участник не в радиусе — сообщение **хранится на телефоне отправителя** в статусе «⏳ Ожидание».
- Как только получатель появится в радиусе (BLE discovery) — отправка происходит автоматически.
- Системное сообщение: «Иван вне зоны. Доставка отложена.» / «Иван получил N сообщений.»

**Шапка группы:**
- Название + «3 из 5 в сети».
- Список участников (горизонтальный скролл чипов):
  - Зелёная точка = в сети.
  - Серая точка = вне зоны.
- Тап на (i) → список участников, добавить (если есть E2E) / исключить.
- **Очистить историю** — удаляет все сообщения в группе (только локально).

---

### 2.7. Отправка различных форматов данных

| Формат | Канал | Размер | Особенности |
|---|---|---|---|
| **Текст** | BLE / Wi-Fi Direct | ∞ | Мгновенно. |
| **Фото** | Wi-Fi Direct | До 10 МБ | CameraX или галерея. Прогресс загрузки. |
| **Файл** | Wi-Fi Direct | До 50 МБ | Любой тип. Иконка + размер. |
| **Геолокация** | BLE / Wi-Fi Direct | < 1 КБ | Координаты в текстовом виде. |

**Прогресс передачи файлов:**
- Индикатор в сообщении (0–100%).
- При обрыве связи — retry вручную (докачка в MVP не поддерживается).

---

### 2.8. Состояния сообщений

```
[Ты нажал отправить]
    ↓
[В очереди] ⏳ — получатель не в радиусе. Хранится на твоём телефоне.
    ↓
[Отправлено] ✓ — пакет ушёл в Bluetooth/Wi-Fi Direct эфир.
    ↓
[Доставлено] ✓✓ — получатель прислал Ack.
    ↓
[Прочитано] 👁 — получатель открыл чат (опционально, отключается).
    ↓
[Ошибка] ❌ — таймаут, нет Ack, retry вручную.
```

**Для групп:** статус «Доставлено 3 из 5». Тап — показывает, кто именно.

---

### 2.9. Очистка истории

- Доступна в деталях чата (1-to-1 или группа) через меню (⋮).
- Удаляет все сообщения из Room БД для данного conversation_id.
- **Только локально.** У собеседников сообщения остаются.
- Подтверждающий диалог: «Удалить всю историю переписки? Это действие нельзя отменить.»

## 4. Безопасность и хранение данных (MVP)

### 4.1. Криптография
- **Identity Keys:** ECIES P-256, Android Keystore (non-exportable).
- **Session Keys:** AES-256-GCM, генерируется для каждого сообщения.
- **GroupKey:** AES-256, хранится в БД, зашифрован master-key из Keystore.

### 4.2. Хранение (Room + SQLCipher)
- Room Database, зашифрована SQLCipher.
- Master-key для SQLCipher в Android Keystore.
- **Таблицы:**
  - `contacts` (id, name, public_key, last_seen).
  - `conversations` (id, type: direct/group, name, created_at).
  - `messages` (id, conversation_id, sender_id, encrypted_payload, timestamp, status, mime_type, file_path).
  - `group_members` (group_id, contact_id, joined_at).
  - `pending_queue` (message_id, target_user_id, retry_count) — для store-and-forward.
  - `settings` (key, value).

### 4.3. Защита от кражи телефона
- PIN / Biometric — обязательны.
- Таймаут авто-выхода (настраивается).
- Keystore: приватные ключи non-exportable.

### 4.4. Что НЕ хранится
- Нет облачных бэкапов.
- Нет синхронизации.
- История только на этом устройстве.

## 6. Roadmap

### v1.1 — Улучшение связи и защита от атак
- **Wi-Fi Direct P2P_CLUSTER:** групповые соединения до 8 устройств, лучшая масштабируемость.
- **Постоянное сканирование в фоне:** BLE advertising/scanning при закрытом приложении (с ограничением по батарее).
- **Anti-replay (nonce):** в каждый пакет добавляется `timestamp + nonce`. Получатель запоминает последние 100 nonce и отбрасывает дубликаты. Защита от повторной отправки перехваченного пакета.

### v1.2 — Безопасность и точность
- **Duress PIN:** второй PIN для фейкового входа + полное стирание данных (wipe).
- **Screenshot protection:** `FLAG_SECURE` — Android блокирует скриншоты и screen recording внутри приложения.
- **Clipboard auto-clear:** через 60 секунд очищается системный буфер, если там данные из OffGrid.
- **Fingerprint verification:** после QR-обмена отображается отпечаток публичного ключа (последние 8 символов). Пользователи могут сверить голосом/глазами, что ключи совпадают (защита от MITM).
- **Дистанция и статус канала в «Рядом»:** точное отображение расстояния (RSSI) и типа канала (BLE / Wi-Fi Direct). Включается в настройках.

### v1.3 — Темы и кастомизация
- **Светлая тема.**
- **Dynamic Color** (Material3, Android 12+).
- **Аватары:** выбор цвета/букв для контактов и групп.

### v1.4 — Файлы и медиа
- **Докачка файлов** (resume при обрыве).
- **Голосовые сообщения** (AAC/Opus, 30 сек).
- **Самоуничтожающиеся сообщения** (таймер 10 сек / 1 мин).

### v1.5 — Продвинутая криптография и Mesh
- **Double Ratchet (Signal Protocol):** вместо шифрования статичным публичным ключом — цепочка ключей, меняющаяся после каждого сообщения. Даёт Perfect Forward Secrecy: взлом одного ключа не ломает всю переписку.
- **Rotating ID (Resolvable Private Address):** BLE-маяк меняет ID каждые 15 минут. Знакомые контакты вычисляют текущий ID через публичный ключ. Незнакомец не может отследить перемещения.
- **Store-and-Forward через посредников (Mesh):** A → B → C. TTL = 3 (максимум 3 прыжка).
- **Gossip-протокол:** дедупликация, anti-flood.
- **Routing table:** выбор оптимального пути к получателю.

### v1.6 — Экстренные функции
- **SOS Beacon:** экстренный сигнал с гео-меткой, рассылается всем в радиусе.
- **NFC bump:** обмен ключами через приложение телефонов друг к другу.
- **Shake-to-Connect:** встряхивание телефона для быстрого обмена ключами.

### v2.0 — Кросс-платформа
- **Desktop-клиент** (Kotlin Multiplatform) с синхронизацией через LAN.
- **Экспорт/импорт истории** (зашифрованный бэкап на USB/SD).

## 7. Оценка реализуемости

### 7.1. Можно ли это сделать?

**Да, полностью реализуемо.** Все компоненты существуют и документированы:

- **Google Nearby Connections API** — стабильное официальное API от Google для P2P-обмена.
- **Android Keystore** — аппаратная защита ключей на уровне чипа (TEE/StrongBox).
- **SQLCipher** — зрелая библиотека, интегрируется с Room через `SupportFactory`.
- **ML Kit Barcode** — работает офлайн, не требует интернета.
- **CameraX** — стандарт для Android.

**Риски:**
- Nearby Connections API требует Location Permission (даже если геолокация не используется) — это ограничение Android.
- На некоторых китайских OEM (Xiaomi, Huawei) фоновый BLE может убиваться системой. Для MVP это приемлемо, т.к. сканирование в foreground.
- Wi-Fi Direct требует, чтобы оба устройства одновременно были в режиме поиска — UX-челлендж, но решаемый.
- MVP использует статичный `user_id` в BLE-эфире (нет Rotating ID). Это допускает теоретический tracking, но не влияет на E2E-шифрование. Защита от tracking — в Roadmap (v1.5).
